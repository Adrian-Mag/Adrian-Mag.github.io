Mechanism, Not Trust

Movement III · What you can change

Act 8 Current as of July 2026

Where text stops being enough. Deterministic interception that runs whether or not the model cooperates. Includes the honest limitation: this is a blocklist, it over-blocks, and it has gaps. A mechanism without a stated threat model is marketing.

Suppose an instruction says, “Do not edit the generated search index directly.” That is useful guidance. It can also be forgotten, displaced by a long conversation, or ignored by a model that has found what it thinks is a quicker route.

A hook changes the location of the decision. Instead of asking the model to remember a rule, the harness pauses at a lifecycle event and runs ordinary code. For a tool call, that code can inspect the proposed input before the tool runs and return a verdict. The model proposes; the mechanism decides.

A real hook, built for this page

The exhibit below comes entirely from this public website repository. It protects media/search-index.json, a generated file that should normally be replaced by running python3 tools/build_search_index.py. The policy is deliberately small: permit that exact rebuild command, deny every other Bash command containing the protected path, and allow everything else.

These are not invented outcomes. On 21 July 2026, a recorder sent four documented PreToolUse payloads to the exact hook process on standard input and captured its output. It classified the candidate commands but never executed them. One additional ephemeral Codex session produced a live denial: the harmless rg command in the third button was stopped before it ran.

Codex-specific, checked 24 July 2026. The event name, JSON fields, discovery rules, and denial response shown here belong to the current Codex hook interface. They are harness behaviour, not a property of a language model or a universal agent protocol.1

Open the mechanism

The cards expose the complete public artifacts. The first is the policy code. The second is the wiring that asks Codex to run it before Bash. The third is a screened extract of the live denial. They are text, not screenshots, so the exact rule and event can be inspected.

The threat model is the product

This hook is designed to reduce one narrow failure: an agent accidentally touching a generated file through a plainly written Bash command. It is not designed to stop a hostile program. The two right-hand buttons make the boundary visible.

The safe read is a false positive. It contains the protected path, so the hook blocks it even though rg would not write anything. The constructed-path example is a false negative. The full filename never appears as one string, so the hook allows a command whose apparent intent is deletion. That command was only classified by the recorder; it was not executed.

More careful parsing could shrink both errors, but it would not turn this particular hook into a complete security boundary. In current Codex, some specialised paths may bypass the normal hook path, hosted tools such as web search are not covered, project hooks depend on trust, and malformed responses using unsupported fields can fail to block.1 Matching command hooks for the same event can also run concurrently, so one hook is not a global ordering mechanism for all other hooks. The useful claim is smaller: for an event the harness exposes, valid code can make a deterministic decision outside the model.

Permissions are not just another hook

A hook is user-supplied lifecycle code. A sandbox is an enforced boundary around what spawned commands may read, write, or reach over the network. An approval policy decides when the agent must stop and ask before crossing that boundary. Current Codex documentation treats these as two controls that work together.2

Hook

Custom policy at a named event. Flexible, inspectable, and only as complete as its matcher, code, response, trust, and event coverage.

Sandbox and approval

Harness controls around execution. The sandbox constrains the command; the approval flow mediates requests to cross the chosen boundary.

The sequence now has three distinct levers. AGENTS.md puts durable advice into context. A skill reveals a detailed procedure when it is relevant. A hook or permission boundary moves a decision out of prose. None changes the model. Each changes the machine around it.
