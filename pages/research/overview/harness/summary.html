Summary Current as of July 2026

The machinery exists to support verification and audit while making its limits visible.

The model is not the whole machine. It predicts the next token from the context it receives. The harness decides what that context contains, which tools may be called, what checks run, where results are stored, and whether a later session can recover the work.

A bare chat box can feel brittle while a carefully built workspace feels capable because the latter supplies ordinary machinery: instructions, files, retrieval, permissions, tools, validation, and a loop that puts the result of one action into the next request.

The levers, in order

NeedWorkspace leverWhat it cannot promise
Persistent guidanceAGENTS.mdThat the model follows every word
A reusable procedureA skill with instructions and optional scriptsPermission to bypass the harness
A rule that must runHook, sandbox, test, or approvalComplete security without a threat model
A new capabilityA tool contract and handlerCorrect selection or correct results by itself
ContinuityFiles, plans, evidence, and a checked handoffPerfect memory or an unchanging summary

Build an instrument, not a story

The public examples in this series come from this website workspace: instructions, a skill and validator, a hook policy, a tool handler, recorded checks, and the relationships between them. They are useful precisely because they can be inspected, tested, or corrected. The interactive map gathers that structure on one page.

Explore the workspace’s agentic structure

Use the smallest lever that makes the behaviour legible. Add a file before a framework. Add a test before a second agent. Add a tool only when a named operation needs a contract. Add orchestration only when the graph buys a boundary, evidence, or parallelism that a single loop cannot.

The honest limit

None of this turns a language model into an authority. It can still misunderstand a request, select the wrong file, invent a claim, or follow a plausible route through the wrong graph. The safeguard is a design that leaves evidence behind: inspectable source, narrow checks, explicit uncertainty, and a human who can stop or reverse the change.

That is the machine around the model. Not a promise that the model will be right, but an instrument for finding out when it is not.
