Act 10 Current as of July 2026

Context as the budget everything competes for. Retrieval as context assembly, not magic. Memory as files. Compaction, and why long sessions degrade.

A model only knows the material that arrives with the request. In this workspace, that material can include the task, selected instructions, source files, tool results, and a small amount of state. None of it is the model’s memory. It is a packet assembled by the harness, then discarded when that request ends.

That makes context a budget, not a library. An instruction that helps on every task earns a place near the start. A detailed procedure belongs in a skill until it applies. A source file is read when the task makes it useful. The order matters as well as the size: long-context research finds that relevant material can be used less reliably in the middle of an input.1

Retrieval is context assembly

Retrieval is the act of choosing what to add next. It can be a search over embeddings and chunks, but it can also be a direct file lookup. This workspace uses the second form constantly: the task points to a plan, the plan points to a source dossier, and the agent reads only the relevant section. The result is still retrieval because it changes the next context packet.

The historical RAG paper paired generated text with retrieved material; the modern phrase is often used more loosely for chunk, search, and prompt assembly. The important distinction is practical: retrieval does not make the model remember a repository. It gives a particular request a carefully selected view of one.2

Memory has a place to live

For this workspace, durable continuity lives in files. The tracked plan and source dossier record public decisions and evidence. The local control pack records the current handoff and checks whether it still applies to the Git state. The split is deliberate: a public plan should be reviewable; live control state should not silently become a public exhibit.

Long sessions eventually need compression. A summary can retain a next safe action and discard a long trail of intermediate work, but it is not a replacement for source. The website-control workflow therefore checks Git before trusting its handoff. When the state and the files disagree, the files win.

Context engineering, checked 24 July 2026 Context windows, retrieval mechanisms, compaction, and prompt caching are harness behaviour, not a new faculty of the language model. The practical design question is always the same: what should this next request see, and what evidence lets us correct it when it is wrong?
