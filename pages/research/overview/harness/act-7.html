Packaging Expertise

Act 7 Current as of July 2026

Progressive disclosure: a short description sits in the initial catalogue; the body loads on demand. Context is finite, and everything loaded competes with everything else.

At the end of the previous act, a small instruction file reached a natural limit. One repository fact belongs in AGENTS.md. A detailed continuity procedure, a state validator, and the instructions for interpreting its result do not. Loading all of that before every task would make the model read a maintenance manual while it was trying to change one sentence.

A skill is a way to put that material on a shelf and give the harness a good index card. The index card is designed to be cheap enough to show. The book comes down only when the task needs it.

A directory, not a new intelligence

In the open Agent Skills format, a skill is a directory with one required file: SKILL.md. Its frontmatter gives the skill a name and describes what it does and when it applies. The Markdown body contains the working instructions. Optional directories can hold scripts, references, templates, images, or other resources.1

Nothing in that definition changes the model. A skill is not training, memory, or a new model capability. It is a package the harness knows how to discover and reveal. The useful idea is not the filename. It is progressive disclosure.

At the first stage, the description has one job: help the harness decide whether this skill belongs in the task. A website task is a plausible match; an unrelated calculation is not. At the second stage, the body supplies the workflow. Only when the workflow reaches validation does the third component become useful.

That is not compression. The missing text has not been squeezed into the description. It is absent from context until the harness or agent goes to fetch it.

Open the working parts

The control pack itself is intentionally local-only. These are screened teaching excerpts and a real run, published by request. Live handoff, state, and configuration records are not included.

The description is a routing rule

The description is not a miniature manual. It needs to say what the skill does and when to use it. In current Codex, the initial catalogue contains the name, description, and file path. The full body is loaded after explicit selection or when the task matches the description. 2

Implementations checked 24 July 2026 The three-tier shape comes from the open Agent Skills specification. Exact search paths, catalogue budgets, invocation controls, and context lifecycle are harness behaviour. The shared file format does not make any one client’s loading behaviour a law of language models.

A vague description such as “helps with documents” saves words but destroys the signal used for routing. A useful description names the task, the relevant inputs, and the boundaries. It is closer to the label on a laboratory drawer than to the contents of the drawer.

Automatic selection is still a model decision. A good skill can fail to trigger, or trigger for the wrong request. Most supporting harnesses also offer an explicit invocation for cases where the user wants certainty. Triggering and quality are separate tests: first ask whether the right tasks load the skill, then ask whether the loaded workflow improves the result.

The body can carry a runnable procedure

The website-control body does not put every check in its frontmatter. Its 120 lines say which state files matter, when to record a handoff, and when to invoke the local entry command that performs validation. The body is the bridge between a natural-language trigger and an actual command.

Optional scripts change the shape again. They let a skill package a repeatable calculation, validator, or converter beside the instructions. Here, the instructions say when to run the validator and how much to trust its result; the script checks structural facts deterministically. The agent must still run it through a tool, and the harness’s permissions still decide whether that request is honoured. A skill can explain a procedure and carry its implements; it does not bypass the machine around the model.

The validator does not certify prose, citations, or visual quality. It checks only the control structure it was written to check. This division of labour is useful: prose tells the agent what the result means, while code makes a narrow, repeatable test harder to forget or improvise.

The complete control pack remains local. The public page shows only safe excerpts needed to teach the pattern, not its live handoff, current-state, or configuration records. A skill can therefore bundle useful local machinery without turning every working file into public documentation.

Choose the smallest durable lever

If the need is...Put it in...
A fact or rule that should accompany nearly every task in one repositoryAGENTS.md
A reusable workflow with task-specific instructions, references, or scriptsA skill
A property that must hold even when the model ignores its instructionsA hook, permission, test, or sandbox
A new way to sense or change the worldA tool

A skill occupies the useful middle. It is richer than one always-loaded instruction file and cheaper than putting an encyclopedia into every prompt. It packages the part of expertise that can be written down: the order of work, the questions to ask, the references to consult, the checks that catch familiar errors.

It still asks the model to follow text. When following text is not good enough, the next lever changes from advice to interception.
